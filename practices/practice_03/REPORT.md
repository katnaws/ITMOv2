# REPORT: локальная модель и OpenCode

## Оборудование и версии

- CPU/GPU: Apple M5, встроенный GPU (Metal, 10 GPU-ядер).
- RAM: 16 GB.
- OS: macOS 26.5.1, build 25F80.
- OpenCode: 1.18.31.
- Ollama: 0.34.4.
- Python: 3.10 или новее; в проекте используется только стандартная библиотека.

`ollama ps` во время прогона показал `100% GPU`; модель не работала только на CPU.

## Модели и параметры

Базовая модель во всех режимах: `qwen3.5:4b` (4.7B параметров, квантизация Q4_K_M).

| ID Ollama | Назначение | Контекст | Вывод | Temperature |
|---|---|---:|---:|---:|
| `itmo-experiment:latest` | изолированные вопросы | 4096 | 1024 | 0.2 |
| `itmo-agent:latest` | интерактивный `local-guide` | 16384 | 1024 | 0.2 |

Модель 4B Q4_K_M выбрана как компромисс между качеством и 16 GB общей памяти. 4k достаточно для четырёх файлов демо; 16k даёт запас для интерактивного агента и не повторяет избыточный для этой машины контекст 32k/64k.

В оба Modelfile добавлен `/no_think`. В OpenCode для моделей также указано `reasoningEffort: none`: OpenCode обращается к OpenAI-совместимому `/v1`, и без этого параметра Qwen могла израсходовать весь лимит на скрытое рассуждение и вернуть пустой финальный ответ.

## Конфигурация OpenCode и изоляция

Локальный конфиг: `lab/demo/opencode.json`. Провайдер `ollama` использует `http://localhost:11434/v1`.

Применяются два режима:

1. Интерактивный `local-guide` использует `itmo-agent`. Ему разрешены только `read`, `glob`, `grep`; все остальные действия запрещены. Живой smoke-тест вызвал `grep` и корректно нашёл `demo/service.py:4`.
2. Контролируемые QA-запуски используют `itmo-experiment`. Каждый вопрос запускается в новой сессии, четыре файла `demo/` передаются явно, а все инструменты запрещены через `OPENCODE_CONFIG_CONTENT`. Эталоны и отчёт в тестовый контекст не передаются.

## Воспроизведение

Из корня репозитория:

```bash
make -C practices/practice_03/lab build-models
make -C practices/practice_03 test
make -C practices/practice_03/lab qa
make -C practices/practice_03/lab compare
```

Отдельный вопрос можно повторить, например:

```bash
cd practices/practice_03/lab
python3 qa.py --questions 4
```

Интерактивное демо:

```bash
cd practices/practice_03/lab/demo
opencode
```

В OpenCode нужно выбрать `local-guide` / `ollama/itmo-agent`.

## Baseline и system prompt

Оба запуска в `experiment.py` используют одинаковую чистую `qwen3.5:4b`, temperature 0.2, seed 42, контекст 4096 и `think=false`. Отличается только наличие `system.txt`.

| Режим | Wall time | Токенов ответа | Скорость | Наблюдение |
|---|---:|---:|---:|---|
| baseline | 5.62 s | 196 | 36.52 tok/s | верно заметил отсутствие данных, но добавил спекуляцию о «чаще всего» используемых CI |
| system | 2.14 s | 75 | 40.58 tok/s | дал требуемый отказ и краткое основание без предположений |

В этом запуске system prompt не «исправил» полностью неверный baseline: baseline тоже заметил отсутствие CI. Эффект состоял в том, что system-ответ был короче, быстрее и не добавлял догадок.

Сырые записи: `lab/results/experiment/baseline.json` и `lab/results/experiment/system.json`.

## Ограничения и выводы

- 4B-модель может давать неловкие формулировки, поэтому даже ответы со ссылками нужно сверять с кодом.
- Правильная команда или имя файла не гарантируют правильную строку; в оценке нужно учитывать и качество основания.
- Для Qwen3.5 через OpenAI-совместимый endpoint критичен `reasoningEffort: none`; одного `/no_think` в system prompt оказалось недостаточно.
- Read-only-права не заменяют изоляцию контекста. Поэтому в QA отдельно запрещены все инструменты и передаются только файлы `demo/`.
- Локальный помощник пригоден для поиска и кратких вопросов по коду, но его выводы нельзя принимать без проверки исходников.
