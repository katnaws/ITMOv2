# Study Space — UI-спека (после согласования)

Фича: перенос дедлайна существующего задания.
Код не меняем на этом этапе; это итоговое описание поведения UI и формата API, согласованное с логикой и проверенное по исходникам практики 4.

HTTP/MCP контракт (проверен по коду)
- Endpoint: POST /api/tools/update_task_deadline?mode=real|demo
- Body: { task_id: integer, deadline: string YYYY-MM-DD } (additionalProperties: false)
- Успех: HTTP 200, тело — MCP envelope { content: [{ type: "text", text: JSON-строка задачи }], isError: false }.
- Ошибка валидации/бизнес-логики: HTTP 400, либо MCP envelope { isError: true, content[0].text }, либо bridge-ошибка { error: string }.
- MCP недоступен: HTTP 502, тело { error: "MCP unavailable: ..." }.
- После успеха UI вызывает GET /api/state?mode=real|demo.

Изменения в UI относительно before
- «Сохранить» отключена при той же дате (same-date) — локальный no-op. На сервере вызов идемпотентный и возвращает объект без изменений (успех 200).
- В модалке парсим MCP envelope успеха: берём updated task из content[0].text (JSON); однако обновление UI выполняем через последующий GET /api/state.
- Ошибки отображаем по тексту из content[0].text (MCP) или по полю error (bridge), на русском.

Поведение UI
- Точка входа: icon-button «Перенести срок» рядом с отображаемой датой в строке задания, aria-label «Перенести срок: <название задания>».
- Модалка «Перенос дедлайна»:
  - Read-only: название и текущий дедлайн в формате ru-RU.
  - Поле даты: type=date, name=deadline, required, автофокус, предзаполнено текущей датой. Подсказка: «Формат ГГГГ-ММ-ДД. Сегодня не считается просроченным. Разрешены прошедшие даты.»
  - Кнопки: «Отмена» (secondary) и «Сохранить» (primary).
- Валидация и состояния:
  - «Сохранить» disabled, если: отправка (saving), пустая/невалидная дата, дата не изменилась.
  - Ошибка — inline `.form-error` (role=alert), текст на русском.
  - Успех — toast «Дедлайн перенесён».
- Доступность: фокус на поле даты; модалка перехватывает фокус; ESC/backdrop закрывают, если не идет сохранение; все элементы доступны клавиатурой.

Режимы и защита от гонок
- Пока модалка переноса открыта, блокируем переключатель режима (real/demo), чтобы исключить отправку в другую БД. Закрытие модалки («Отмена») не блокируется.
- На время saving блокируем повторные отправки, ESC/backdrop/крестик — не закрывают модалку.
- Фоновые refresh (30 с) не перезатирают введённую дату — форма остается контролируемой локально; обновление состояния выполняется только после успеха.
- Родительские busy/refresh состояния восстанавливаются после ошибок — страничный error-banner отрабатывает и не оставляет UI «занятым».

Что обновляется после успеха
- Строка задания: дата и метка просрочки (.task-date.late).
- Сортировка: применяется порядок, полученный от backend после GET /api/state.
- Сводка: пересчитывается число просроченных; статус/прогресс пересчитываются как в практике 4.
- Правая колонка: «На горизонте» и (возможный) новый next_task.

Правила дат (инварианты)
- Europe/Moscow, дата без времени (YYYY-MM-DD).
- Прошлые даты разрешены; «сегодня» не просрочено; статус done никогда не просрочен.
- Меняем только deadline; title/course/status/created_at/id неизменны.

История MCP
- Новый инструмент отображается как update_task_deadline; человекочитаемая метка: «Перенос дедлайна».

Источник проверки формата
- practices/practice_04/dashboard/server.py — bridge: 200 успех (isError=false), 400 ошибки MCP/валидации, 502 недоступность MCP; Content-Type=application/json обязателен; размер ≤16KB.
- practices/practice_04/mcp/study_tracker/server.py + mcp/stdio.py — MCP envelope всегда содержит поле isError (true/false) и content[0].text.
