Согласование (логика ↔ UI) — Redaction API

Контекст
- Логика (before): POST /api/reviews, контракт и ошибки как в logic_spec.before.md.
- UI (before): POST /api/review/redact и связанные допущения (preview/redacted и пр.).

Таблица расхождений (факты → предложение логики)

1) Endpoint
- UI: POST /api/review/redact
- Логика: POST /api/reviews (из бэклога practice_01)
- Предложение: сохранить исторический /api/reviews из бэклога; UI может использовать /api/reviews. Если критично иметь глагольный ресурс, компромисс: алиас /api/reviews (основной), /api/review/redact (временный 307). До ДЗ — единый путь /api/reviews.

2) Поле запроса
- Обе стороны: diff (string)
- Уточнение логики: обязательное поле, Content-Type: application/json
- Unicode: считаем лимит в кодовых точках Python (len(diff) ≤ 20000). Предложение: согласовать именно число символов, не байт.

3) Лимиты/счётчики
- UI: упоминает лимит; нужно явное число
- Логика: 20000 символов
- Предложение: лимит 20000 символов; при превышении — 413.

4) Ответ и redacted preview
- UI: нужен ли предварительный redacted preview?
- Логика: success: summary + ≤3 risks + checks; превью исходного текста не возвращаем (из соображений безопасности)
- Предложение: НЕ возвращать полный redacted diff в теле ответа. Если UI нужен индикатор редактирования, можно добавить поле "redaction": { "secretsFound": boolean, "count"?: number } без передачи текста. По умолчанию не добавляем — минимальный контракт.

5) Ошибки
- UI: 422/413/502; нужны коды и форматы
- Логика: 422/413/502 с error.code: UNPROCESSABLE_CONTENT / CONTENT_TOO_LARGE / LLM_UPSTREAM_ERROR
- Предложение: принять коды логики; message — свободный текст для пользователя, UI ориентируется на error.code.

6) Deterministic stub
- UI: подтверждает stub
- Логика: stub получает только redacted diff; таймаут эмулируется флагом (например, STUB_TIMEOUT)
- Предложение: принять; stub детерминированный, повторяемый.

7) Безопасность DOM/поля ввода
- UI: безопасный рендеринг, исходный текст только в textarea (не HTML), no persistence
- Логика: поддерживает; сервер не возвращает сырой текст/секреты; логика не хранит вход.
- Предложение: согласовано.

8) Ответы и состояния
- UI: нужны явные форматы
- Логика: 200/422/413/502 схемы определены; ≤3 risks; не логировать сырой diff.
- Предложение: принять форматы логики (см. YAML ниже) без redacted preview текста.

Итоговое предложение (для контракта): см. contract.proposed.yaml
