Согласование (UI ↔ логика) — Redaction API

Контекст
- UI (before): POST /api/review/redact; success содержит summary/redacted/secrets_count/checks/risks; мягкая проверка «похож на diff»; лимит 20000; безопасность DOM и отсутствие хранения сырых данных.
- Логика (proposed): POST /api/reviews; success summary/risks(≤3)/checks(str[]); ошибки 422/413/502 с error.code; без возврата redacted текста; лимит 20000 символов по Unicode.

Решения и выравнивание
1) Endpoint
- Принято: основной путь POST /api/reviews (из бэклога). UI использует /api/reviews. Алиас /api/review/redact не требуется в минимальной версии.

2) Тело запроса
- Принято: JSON { diff: string }, Content-Type: application/json. Unicode лимит считается по количеству символов (Python len), не по байтам.

3) Лимит
- Принято: 20000 символов. При превышении сервер возвращает 413 с error.code=CONTENT_TOO_LARGE. UI также локально блокирует отправку при >20000.

4) Валидация «похож на diff»
- Принято: мягкая проверка на клиенте (предупреждение, но отправка разрешена). Сервер при необходимости вернет 422/UNPROCESSABLE_CONTENT.

5) Успешный ответ и форматы
- Принято: логический формат без возврата redacted текста. UI выводит:
  - summary: string
  - risks: массив до 3 элементов с полями { file?: string, line?: number, evidence?: string, risk: string }
  - checks: массив строк (именованные проверки)
- Примечание: UI не показывает исходный diff; вывод безопасный текстовый.

6) Ошибки
- Принято единый формат: { error: { code, message } }.
- Коды: 422 → UNPROCESSABLE_CONTENT; 413 → CONTENT_TOO_LARGE; 502 → LLM_UPSTREAM_ERROR.
- UI ориентируется на error.code для выбора сообщения. message показывается как пользовательский текст (без стеков).

7) Наблюдаемость/заглушка
- Принято: детерминированная заглушка. UI показывает стабильный результат: summary + до 3 рисков + список checks. Поля score/traceId не требуются.

8) Безопасность и хранение
- Принято: исходный diff остается только в textarea (для редактирования пользователем), не логируется и не сохраняется в persistent storage; DOM-рендеринг безопасен (plain text), без вставки HTML.

9) Unicode подсчет
- Принято: лимит в символах Unicode (кодовые точки). UI счетчик синхронизирован с серверной логикой.

Оставшиеся расхождения / замечания
- Нет критических. UI отказывается от полей redacted/secrets_count/trace_id в минимальном контракте, чтобы совпасть с логикой.

Итог
- Контракт, предложенный логикой (contract.proposed.yaml), совместим с UI после вышеуказанных корректировок UI-ожиданий.
