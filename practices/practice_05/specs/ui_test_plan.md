UI Test Plan — «Diff Secret Redactor» (по ui_spec.after.md)

Цель
- Проверить минимальный реальный UI на соответствие согласованному контракту и требованиям доступности/безопасности.

Окружение
- Локально открыть practices/practice_05/web/index.html в браузере (без сервера) для проверки клиентской логики.
- После запуска backend (same-origin http://localhost:8000) — сквозные проверки POST /api/reviews.

Критерии и сценарии
1) Пустой ввод/whitespace
- Вставить пустую строку и пробелы: кнопка «Review» неактивна; aria-live сообщает об ошибке «Введите diff».

2) Счетчик Unicode (лимит 20000)
- Вставить 3 символа, включая emoji (😀) и комбинированные символы — счетчик отображает корректное число code points.
- Вставить 20001 символ (скриптом или пейстом): кнопка блокируется; отображается ошибка лимита; не отправляет запрос.

3) «Похож на diff» (мягкое предупреждение)
- Вставить текст без «diff --git», «+++ », «--- », «@@»: показывается предупреждение; кнопка активна, можно отправить.
- Вставить корректный patch — предупреждение исчезает.

4) Loading/блокировка дублей
- Нажать «Review»: кнопка дизейблится, появляется «Загрузка…», повторное нажатие блокируется.

5) Успех 200
- При ответе 200 c JSON { summary, risks (≤3), checks[] }: UI показывает summary; риски (file/line/evidence/risk) и checks как список строк.
- Исходный diff нигде не отображается.

6) Ошибки
- 413 CONTENT_TOO_LARGE: показать локализованное сообщение «Лимит 20000 символов превышен». Кнопка возвращается в активное состояние после ответа.
- 422 UNPROCESSABLE_CONTENT: «Невалидный diff. Проверьте формат.»
- 502 LLM_UPSTREAM_ERROR: «Сервис ревью временно недоступен. Повторите позже.»
- Network/timeout: «Сеть недоступна или таймаут. Повторите позже.»

7) Очистка
- Нажать «Очистить»: подтверждение; textarea, счетчик, статусы и результаты очищены; кнопка «Review» снова неактивна.

8) Доступность
- Labels связаны с textarea; навигация с клавиатуры; видимый фокус.
- aria-live=polite для статусов/ошибок; role=status для блока результата.

9) Безопасность UI
- Нет использования innerHTML для серверных строк; только textContent.
- Нет логирования в консоль; нет localStorage/session/IDB.

Примечание
- Redaction выполняется на backend. Очистка textarea — это действие UI, не доказательство маскирования.
