UI спецификация (before) — сервис «Diff Secret Redactor» (только UI)

Цель
- Минимальный, реальный веб‑интерфейс, который позволяет пользователю вставить diff и отправить его на «обезличенный» ревью: перед отправкой на ревью логика должна удалить/заменить секреты на [REDACTED]. В этой before‑спеке определяем UI, предполагаемый API контракта (предложение), состояния, валидации и требования по безопасности клиента. Код не генерируем.

Видимая функциональность
- Текстовое поле (textarea) «Diff input» для вставки diff.
  - Подсказка: «Вставьте unified diff (git diff/PR patch). Сырые секреты будут скрыты перед ревью».
  - Счетчик символов и ограничение 20000 символов. При превышении: блокировка отправки и ошибка.
  - Label связан с полем (for/id), aria‑описание с подсказкой.
- Кнопка «Review».
  - Disabled, если: поле пустое; превышен лимит; идет загрузка.
- Индикатор загрузки (текст «Загрузка…» и aria‑live=polite) во время запроса.
- Блок «Результат ревью».
  - В случае успеха:
    - Короткий summary: строка «Ревью выполнено» и количество обнаруженных секретов, замененных на [REDACTED] (если доступно).
    - Раздел «Risks»: краткий список рисков/замечаний (если есть).
    - Раздел «Checks»: краткий список проверок, которые прошли/не прошли.
    - Безопасный вывод: ни сырые секреты, ни исходный сырой diff не отображаются. Показать только безопасные извлеченные сведения из ответа.
  - В случае ошибки:
    - Показать сообщение ошибки пользователю без деталей сервера/стека, в т.ч. варианта валидационной ошибки, лимита или ошибки сервера.
    - Предложить повторить позже и/или исправить ввод.
- Ссылка «Очистить» для сброса формы (с подтверждением), без сохранения данных.

Доступность и UX
- Все интерактивные элементы доступны с клавиатуры, фокус видим.
- Поля имеют label, aria‑describedby; роли/aria‑live для статусов.
- Ошибки озвучиваются screen‑reader через aria‑live.
- Кнопки и ссылки имеют контраст и четкие названия.

Валидация на клиенте
- Обязательность: diff не пустой.
- Формат: базовая проверка, что diff содержит строки, начинающиеся с «+++ »/«--- » или «diff --git», либо «@@» хунк‑маркер; если нет — предупреждение и разрешение отправки по решению пользователя? (см. вопросы).
- Лимит: максимум 20000 символов. При >20000: ошибка, кнопка disabled.
- Размерные поля: no‑wrap, но визуально мягкий перенос.

Безопасность клиента
- Не сохранять сырой diff в localStorage, sessionStorage, IndexedDB или логах.
- Не логировать сырой ввод/ответ в консоль.
- Не вставлять ответ как HTML, только текст/безопасный рендер.
- Не отображать исходный diff или потенциально секретные фрагменты.

Предложение API контракта для согласования (черновик UI)
- Endpoint: POST /api/review/redact
- Request (JSON):
  {
    "diff": string  // исходный diff от пользователя, до редактирования, до передачи в заглушку ревью логики; сервер обязан выполнить редакцию секретов перед любыми внешними действиями
  }
- Request ограничения:
  - Content-Type: application/json
  - Максимум 20000 символов diff
  - UI не добавляет метаданные пользователя
- Success Response 200 (JSON):
  {
    "summary": string,                 // краткая строка «Ревью выполнено» или иная сводка
    "redacted": boolean,               // true, если секреты обнаружены и замаскированы
    "secrets_count": number,           // сколько секретов было замаскировано (0, если не найдено)
    "checks": Array<{ name: string, status: "pass"|"fail"|"warn", details?: string }>,
    "risks": Array<{ title: string, severity: "low"|"medium"|"high", hint?: string }>,
    "trace_id"?: string                // для отладки на сервере, не показывается пользователю напрямую
  }
- Validation Error 400 (JSON):
  {
    "error": "validation",
    "message": string,                 // короткое дружелюбное сообщение для UI
    "fields"?: Array<{ field: string, issue: string }>
  }
- Limit Error 413 (JSON):
  {
    "error": "limit",
    "message": string
  }
- Server Error 5xx (JSON):
  {
    "error": "server",
    "message": string
  }

Состояния UI
- Idle: форма доступна, кнопка неактивна пока поле пусто/ошибки.
- Valid: кнопка активна, можно отправить.
- Loading: кнопка disabled, показывается «Загрузка…».
- Success: показывается summary/risks/checks. Нет пересказа diff.
- Error:
  - validation: показать короткое сообщение и подсветить поле.
  - limit: показать «Лимит 20000 превышен».
  - server: показать «Сервер недоступен или ошибка. Повторите позже».

Примечания
- LLM‑ревью — заглушка на стороне сервиса, без внешних запросов: UI этого не меняет, но ожидает стабильные ответы.
- UI не делает предпросмотр редактированного diff и не показывает обезличенный diff для минимальной версии; можно расширить позже.
