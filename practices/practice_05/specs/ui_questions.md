Вопросы к команде логики (для согласования контракта)

API и контракт
1) Подтвердите конечную точку: POST /api/review/redact. Нужны ли префиксы (например, /v1)?
2) Формат запроса: JSON { "diff": string }. Требуются ли дополнительные поля (например, источник diff, repo, branch) или явно без них?
3) Лимит: сервер принимает максимум 20000 символов? Если превышен — 413 или 400? Предпочтительный код и тело ошибки?
4) Валидация формата diff: должны ли мы жестко отклонять «непохожий на diff» текст (400) или допускать с предупреждением? Если отклонять, какие минимальные критерии?
5) Безопасность: подтверждаете, что сервер выполняет редактирование секретов до любых вызовов LLM, даже если сейчас LLM — заглушка?
6) Набор полей ответа успеха: достаточно ли summary, redacted, secrets_count, checks[], risks[]? Нужны ли дополнительные метаданные (например, категории рисков, версии правил)?
7) Формат checks: { name, status: pass|fail|warn, details? } — подтвердите. Есть ли фиксированный список проверок для UI (для подписи), или список динамический?
8) Формат risks: { title, severity: low|medium|high, hint? } — подтвердите. Можно ли severity опционально отсутствовать?
9) trace_id: можно ли всегда возвращать trace_id для корреляции (UI не показывает, но можно копировать по кнопке «Копировать ID» в будущем)?

Ошибки и состояния
10) Ошибки: возвращаете ли единый объект { error: code, message }? Возможны ли дополнительные типы: timeout, auth? (Пока auth не планируем.)
11) Тексты message: можно ли считать, что message безопасен для пользовательского показа (без утечки серверных деталей)?
12) Сервер может детектировать отсутствие сети/внутреннюю ошибку: какой код/тело предпочтительны для UI унификации?

Нефункциональные
13) Таймаут: какой разумный таймаут на сервере/клиенте ожидать? UI по умолчанию покажет «Загрузка…» до ответа, но хотим знать SLA.
14) Локализация: серверные тексты на английском/русском? UI готов к коротким сообщениям.
15) Логи сервера: подтверждаете, что не будете логировать сырой diff и секреты в неизмененном виде?

Расширения (на будущее, для информации)
16) Планируете ли возвращать сводку по типам секретов (например, ключи, токены), чтобы UI мог показывать breakdown без раскрытия содержимого?
17) Хотите ли, чтобы UI отображал обезличенный diff (redacted), если сервер готов отдавать безопасную версию? Сейчас мы не планируем его показывать.
