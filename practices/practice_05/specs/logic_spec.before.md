Спецификация логики (before) — Redaction в POST /api/reviews

Контекст и цель
- Реализуем серверную логику локального Python‑сервиса для очистки секретов в diff перед передачей в LLM (в ДЗ — детерминированная заглушка) и перед любыми логами.
- Выполняем третью User Story из practice_01/product_management.md: «Как инженер по безопасности, я хочу удалять токены, пароли и приватные ключи до вызова LLM, чтобы секреты не покидали доверенный контур».

Endpoint и контракт (предложение для согласования)
- Метод: POST /api/reviews
- Content‑Type: application/json
- Request: { "diff": string } — обязательное поле
- Ограничения: длина diff ≤ 20000 символов
- Успешный ответ 200 OK:
  {
    "summary": string,
    "risks": [ { "file"?: string, "line"?: number, "evidence"?: string, "risk": string } ],
    "checks": [ string ]
  }
  - В ответе не более 3 объектов risks.
  - Внутренние подготовительные данные (prompt/сырой diff) не возвращаются.
- Ошибки:
  - 422 Unprocessable Content — отсутствует поле diff, diff не строка или недопустимый JSON; тело ошибки: { "error": { "code": "UNPROCESSABLE_CONTENT", "message": string } }
  - 413 Content Too Large — diff длиной > 20000; тело ошибки: { "error": { "code": "CONTENT_TOO_LARGE", "message": string } }
  - 502 Bad Gateway — сбой/таймаут LLM‑провайдера; код: LLM_UPSTREAM_ERROR; тело ошибки: { "error": { "code": "LLM_UPSTREAM_ERROR", "message": string } }

Правила безопасности и логирования
- До любой записи в логи и до подготовки prompt выполняется редактирование секретов (redaction) — замена на строку "[REDACTED]".
- Сырые неочищенные diff не логируются и не сериализуются.
- Заглушка LLM получает только redacted‑версию diff.

Правила редактирования секретов (детерминированные)
- Замещаем на "[REDACTED]":
  1) PEM private key блоки: строки между и включая маркеры "-----BEGIN ... PRIVATE KEY-----" и "-----END ... PRIVATE KEY-----".
  2) Явные токены/ключи по типичным паттернам: префиксы sk-, ghp_, jwt‑подобные триплеты base64url с двумя точками (header.payload.signature), AWS‑пары переменных (AWS_ACCESS_KEY_ID/AWS_SECRET_ACCESS_KEY) — значения заменяются.
  3) Пары вида PASSWORD=..., SECRET=..., TOKEN=..., KEY=... (без учёта регистра ключа) — правая часть заменяется.
- Редакция должна быть воспроизводимой и не разрушать остальной текст (сохраняем структуру строк/контекст, где возможно).

Валидация входа и ограничения
- diff обязателен и должен быть строкой.
- Максимальная длина diff — 20000 символов; при превышении — 413 и запрет вызова заглушки.
- На 422 — не вызывать заглушку.

LLM как заглушка
- Никаких внешних запросов; используем детерминированный модуль stub:
  - Принимает redacted diff; возвращает фиксированные summary/risks/checks на основе простых правил (например, наличие маркера [REDACTED] добавляет риск "Secrets were present and redacted").
  - Таймаут/сбой можно эмулировать флагом (например, если строка содержит "STUB_TIMEOUT"), выдавая 502 с кодом LLM_UPSTREAM_ERROR.

Acceptance Criteria (логика)
1) Позитивный сценарий: корректный diff ≤ 20000, содержит секреты → в stub поступает только redacted версия; ответ 200 с summary, ≤3 risks и checks; ни в логах, ни в ответе нет исходных секретов.
2) Невалидный — отсутствует/нестроковый diff → 422 и заглушка не вызывается.
3) Граничный — diff длиной 20001 → 413 и заглушка не вызывается.
4) Ошибка LLM — эмулированный таймаут → 502 с error.code LLM_UPSTREAM_ERROR; содержимое diff не логируется и не включается в ответ.

States/Ответы (явные форматы)
- 200 OK: { summary: string, risks: Array<{file?, line?, evidence?, risk}>, checks: string[] }
- 422: { error: { code: "UNPROCESSABLE_CONTENT", message: string } }
- 413: { error: { code: "CONTENT_TOO_LARGE", message: string } }
- 502: { error: { code: "LLM_UPSTREAM_ERROR", message: string } }

Синхронизация с UI (контракт для согласования)
- UI не отображает сырые diff/секреты; допускается отображение [REDACTED].
- Максимум три риска; ошибки 422/413/502 оформлены как выше.
- Поля response/ошибок стабильны — UI может строить состояния экрана по коду и сообщению.

Out of scope
- Аутентификация, квоты, интеграция с реальным LLM/SDK, лог хранения истории.
