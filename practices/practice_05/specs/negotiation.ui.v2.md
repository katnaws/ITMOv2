Согласование (UI ↔ логика) — ревьюер diff v2

Контекст
- Цель: понятный ревьюер diff с локальной работой пользователя, обязательной серверной очисткой секретов и реальным ревью через VseLLM только по очищенному diff.
- Требования координатора: очистка ТОЛЬКО на localhost Python; в JS не дублировать регэкспы и не пытаться чистить самостоятельно. Внешний вызов — только после отдельной кнопки «Отправить очищенный на ревью».

Принятые решения
1) Endpoints и контракт
   - GET /api/provider → { provider: 'VseLLM', model: string, configured: boolean }
     - Используется для отображения статуса провайдера/модели в UI, без ключей.
   - POST /api/preview { diff: string } → { redacted: string, redactions_count: integer ≥ 0 }
     - Очистка выполняется на сервере (localhost Python). UI НЕ реализует очистку/регэкспы.
     - Лимит: 20000 Unicode code points; при превышении — 413 CONTENT_TOO_LARGE; 422 при невалидном вводе.
   - POST /api/reviews { diff: string }
     - UI отправляет очищенный diff (из preview) в поле diff. Сервер перед внешним вызовом повторно чистит (идемпотентность).
     - Success: { summary: string, risks: Array<{ file?: string, line?: number, evidence?: string, risk: string }>, checks: Array<string> } (≤3 risks)
     - Errors: 422 UNPROCESSABLE_CONTENT, 413 CONTENT_TOO_LARGE, 502 LLM_UPSTREAM_ERROR, 503 PROVIDER_NOT_CONFIGURED.

2) UX и поток
   - Этап 1: пользователь вставляет diff → проверка пустоты/лимита/«похож на diff» (мягкое предупреждение), кнопка «Проверить и скрыть секреты» активна при валидном вводе.
   - Этап 2: UI вызывает /api/preview и показывает «Очищенный diff» (+ счётчик замен redactions_count). Список найденных секретов НЕ показывается.
   - Этап 3: кнопка «Отправить очищенный на ревью» вызывает /api/reviews (с очищенным diff). Отображается результат (summary/risks/checks). Исходный diff нигде кроме textarea не показывается.
   - Любое редактирование исходного diff сбрасывает предпросмотр и отключает кнопку отправки очищенного (инвалидация состояния).

3) Безопасность
   - Исходный diff никогда не отправляется внешним сервисам; наружу уходит только очищенный diff.
   - UI не хранит сырой diff/секреты в local/session/IDB, не логирует их в консоль и не вставляет как HTML (только безопасный текст). Выделение [REDACTED] — безопасными DOM‑узлами.

4) Ошибки и статусы
   - Preview: 422/413 + сетевые; Review: 422/413/502/503 + сетевые.
   - 503 PROVIDER_NOT_CONFIGURED отображается как «Провайдер не сконфигурирован. Попробуйте позже или обратитесь к администратору». Не обещаем, что наличие ключа гарантирует доступность.
   - Управление запросами: дедупликация/блокировка кнопок на время запроса; инвалидация/AbortController для гонок и запоздалых ответов (версионность запроса).
   - Таймауты/ожидание: показать явный индикатор ожидания; серверный SLA 30–90s будет уточнён логикой; UI готов к длительному ожиданию и отмене пользователем.

5) Лимит и валидации на клиенте
   - Пустота/пробелы → disabled и подсказка.
   - Лимит 20000 code points (подсчёт в JS), при превышении — немедленное сообщение и disable.
   - «Похож на diff» — мягкое предупреждение, отправка разрешена.

6) Маркер статуса провайдера
   - UI запрашивает GET /api/provider и показывает провайдера/модель/configured. Баннеров «демо/заглушка» больше нет.

Открытые точки (для логики)
   - Формулировки ошибок (локализация) — оставить message свободным, UI по code выбирает шаблон.
   - Рекомендуемый серверный таймаут и стратегия ретраев для review.

Итог
   - UI принимает предложенный контракт без возражений и фиксирует поток preview→review. Очистка производится только на сервере (localhost Python); UI не дублирует регэкспы.
