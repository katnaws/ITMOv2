# Практика 4 — учебный трекер с собственным MCP

Автор: **впишите ФИО и группу перед сдачей**.

## Что сделано

Собственный MCP `study_tracker` предоставляет четыре инструмента:
`add_task`, `list_tasks`, `update_task_status`, `study_dashboard`.
Они сохраняют учебные задания в SQLite, фильтруют по курсу и статусу,
вычисляют прогресс и показывают просроченные задания.
React-дашборд — дополнительный клиент MCP, а не отдельный обязательный критерий.
Он обращается к Python HTTP-мосту, который вызывает MCP через stdio.

## Зачем нужны подключения

AGENTS.md задаёт правила для агента в репозитории. Skill содержит повторяемый
порядок проверки, чтобы агент не придумывал его заново. Собственный MCP
даёт агенту доступ к данным учебного трекера через инструменты с описанными
аргументами. Runner проверяет работу инструментов и собирает
подтверждения. Post-commit hook добавляет запуск runner после коммита,
когда агент не участвует. Дашборд позволяет наглядно показать данные.

## Устройство skill

В SKILL.md есть frontmatter с названием и описанием, условия применения и
инструкции запуска runner. Источник `./practices/practice_04` указан в opencode.json;
OpenCode обнаруживает skill с ID `auto_check` по пути к файлу.
Skill задаёт порядок действий; выполнение поручено агенту и скриптам.
Это не фоновый наблюдатель файлов. Автоматизацию подтверждают вызов skill
моделью, выполненная shell-команда runner и отдельный запуск Git hook.

## Настоящая демонстрация OpenCode

Сохранены исходный поток событий `logs/opencode_session.jsonl` и компактная
выборка `logs/opencode_evidence.json`. Из событий видно:

1. Агент прочитал AGENTS.md инструментом read.
2. Загрузил skill инструментом skill с аргументом id=auto_check.
3. Вызвал study_tracker_study_dashboard — успешный ответ.
4. Вызвал study_tracker_add_task с датой 2026-02-30 — ошибка.
5. Выполнил bash practices/practice_04/runner.sh — проверки завершились.

Для headless CLI был установлен лимит 90 секунд. Процесс был остановлен
после завершения перечисленных tool calls, до итогового текстового ответа.
Это ограничение явно отражено в журнале; полный успешный выход CLI не заявляется.
Связь MCP также независимо проверена локальными клиентами.

## Проверки и ограничения

Runner проверяет сохранение задач между процессами, фильтры, расчёт
просрочек и прогресса, неверные даты, статусы и ID. Проверка моста
дашборда подтверждает вызовы MCP; при установленных npm-зависимостях
runner также собирает React.
`logs/changes.diff` — снимок незакоммиченных изменений, включая работу,
выполненную до текущего завершения лабораторной.

HTTP-проверка проведена отдельно; её вывод — `logs/dashboard_http_check.json`.
В браузере проверены добавление задания, смена статуса, поиск,
история MCP-вызовов и отсутствие горизонтального переполнения при ширине 390 px.
Скриншот — `logs/dashboard-preview.jpg`.

Hook демонстрировался в изолированной копии: в оригинальном репозитории
коммитов для доказательства не создавалось. В этой копии npm-зависимости
не устанавливались, поэтому hook-демо пропускает React-сборку;
успешная React-сборка отдельно подтверждается основным runner.log.

Данные локальные, без уведомлений и удалённой синхронизации. Дедлайн
включает указанную дату по Москве. Прогресс — доля выполненных заданий.
Деморежим работает с отдельной временной базой, пользовательские данные
не включены в архив сдачи.

## Как воспроизвести

Подробная инструкция — `HANDOFF.md`. Коротко, из корня репозитория:

```sh
npm --prefix practices/practice_04/dashboard ci
make p4-run
make p4-dashboard
```

Демо: http://127.0.0.1:8765/?mode=demo.
Сборка архива: `make p4-pack`.
